# STEP 1.5 — Baseline Article Generation

## Goal

固定したAgent versionを使い、実Evidenceに基づく `article.md` を1本生成する。

STEP 1.5はSTEP 2〜4の設定を行う工程ではない。完了条件は、Article Project内に
Evidence一式と空でない `article.md` が生成され、検証コマンドが成功することである。

## Automation boundary

利用者が入力するのは次の3項目だけとする。

- Article ID
- テーマ
- 想定読者

Project作成、Agent version取得、Git情報取得、Version Snapshot保存、
`PROJECT_STATE.md` への記録、実値入りAgentタスク生成はinitializerが自動実行する。
Version情報を利用者が手作業で転記しない。

ChatGPT WorkのAgent実行自体はローカルPythonから起動できないため、
生成された `AGENT_TASK.md` をAgentへ1回渡すところだけがMVPの明示的な人間境界である。
その後はAgentがPhase 1からEvidence Gate、Article Drafting、Quality Reviewまで連続実行する。

## 0. Prerequisites

STEP 0とSTEP 1が完了し、Agent Repositoryが正式baselineとして使用できる状態であること。

```bash
cd ~/dev/technical-blog-work-agent
source .venv/bin/activate
python --version
git status --short
```

期待値:

```text
Python 3.14.6
git status --short は空
```

dirtyなAgent Repositoryから正式baselineを開始しない。initializerも標準では拒否する。

## 1. 1回のコマンドでArticle Projectを初期化

```bash
export ARTICLE_ID="20260818-mlflow-m5max-001"
export PROJECTS_ROOT="$HOME/dev/technical-blog-projects"
export PROJECT_DIR="$PROJECTS_ROOT/$ARTICLE_ID"

python tools/init_article_project.py \
  --projects-root "$PROJECTS_ROOT" \
  --article-id "$ARTICLE_ID" \
  --topic "M5 Max環境でMLflowの公式チュートリアルを実行する" \
  --audience "MLflowを初めて使用するエンジニア"
```

initializerは次を自動実行する。

```text
Article Projectのディレクトリ作成
PROJECT_STATE.mdの初期化
Agent version / Git commit / branch / dirtyの取得
results/version-snapshot.jsonの保存
PROJECT_STATE.mdへのVersion identity記録
実値入りAGENT_TASK.mdの生成
```

この時点で `article.md` はまだ存在しない。空の先行作成は禁止する。

### 旧initializerで作成済みのProjectを再開する場合

`PROJECT_STATE.md` は存在するが `AGENT_TASK.md` がないProjectでは、削除や再作成を行わず
`--resume-existing` を付けて移行する。

```bash
python tools/init_article_project.py \
  --projects-root "$PROJECTS_ROOT" \
  --article-id "$ARTICLE_ID" \
  --topic "M5 Max環境でMLflowの公式チュートリアルを実行する" \
  --audience "MLflowを初めて使用するエンジニア" \
  --resume-existing
```

この処理は既存のPhase成果物を保持し、現在のVersion Snapshotと `AGENT_TASK.md` を追加する。
以前のVersion Snapshotは `results/version-snapshot.<commit>.json` として保存する。

## 2. Agentを1回だけ開始

ChatGPT WorkのTechnical Blog Agentへ次の1文を渡す。

```text
<PROJECT_DIR>/AGENT_TASK.md を読み、記載されたPhaseを連続実行してください。
Evidence GateがPASSしたらArticle Draftingを実行し、<PROJECT_DIR>/article.mdへ実内容を保存してください。
```

`<PROJECT_DIR>` はinitializerが出力した絶対パスに置き換える。
Article ID、Git commit、Agent versionなどを再入力しない。Agentは
`AGENT_TASK.md`、`PROJECT_STATE.md`、`results/version-snapshot.json` から読み取る。

Agentは計画だけを返して停止せず、次の順で実作業を進める。

```text
Research
  -> Hypothesis
  -> Experiment Design
  -> Environment / Experiment
  -> Analysis
  -> Discussion
  -> Visual Evidence
  -> Evidence Gate
       FAIL -> Missing EvidenceのPhaseへ戻る
       PASS -> article-drafting Skillを実行
  -> article.mdへ保存
  -> Reader-visible Contractを決定的検査
  -> Quality Review
```

実験上の承認、認証、GUI操作、テーマを変える判断など、人間にしか決められない箇所ではAgentが停止して依頼する。
Version情報の転記やPhase成果物のファイル作成を利用者へ依頼してはならない。

## 3. article.mdの生成処理

Evidence GateがPASSしたAgentは、必ず次を実行する。

1. `skills/08-article-drafting/SKILL.md` を読む。
2. `research.md` から `discussion.md`、ログ、画像、Evidence Gate結果を入力としてArticle Draftingを実行する。
3. Qiita掲載用Markdownの実内容を `$PROJECT_DIR/article.md` へ保存する。
4. 空ファイル、見出しだけのダミー、架空Evidenceでないことを確認する。
5. `PROJECT_STATE.md` のPhase 11を `COMPLETED` へ更新する。
6. `results/article-evidence-map.json`を作成する。
7. `python -m evals.check_article_contract --article "$PROJECT_DIR/article.md" --strict --output "$PROJECT_DIR/results/article-contract.json"`を実行する。
8. exit 0の場合だけQuality Reviewを実行し、`results/quality-review.json` を保存する。exit 1なら不足項目へ戻る。

Evidence GateがFAILなら `article.md` を作成せず、Missing Evidenceを記録して不足Phaseへ戻る。

## 4. STEP 1.5の完了を自動検証

```bash
python tools/verify_article_project.py \
  --project-dir "$PROJECT_DIR" \
  --require-quality-review
```

成功時:

```text
OK: STEP 1.5 article project is complete: ...
.../article.md
```

この検証は次の実ファイルが空でないことを確認する。

```text
PROJECT_STATE.md
AGENT_TASK.md
results/version-snapshot.json
research.md
hypothesis.md
experiment-plan.md
experiment-log.md
analysis.md
discussion.md
article.md
results/article-evidence-map.json
results/article-contract.json
results/quality-review.json
```

失敗した場合、STEP 2へ進まない。表示された不足ファイルに対応するPhaseを再開する。

## Completion check

```text
□ 利用者の入力はArticle ID / テーマ / 想定読者だけ
□ Version identityは自動記録された
□ AGENT_TASK.mdが実値入りで生成された
□ 既存Projectの場合は--resume-existingでEvidenceを保持した
□ AgentがPhase 1から連続実行した
□ Evidence Gateを省略していない
□ article-drafting Skillが実行された
□ article.mdが実内容を持って保存された
□ article-evidence-map.jsonが選定判断と失敗Evidenceを含む
□ article-contract.jsonのacceptance.passがtrue
□ Quality Review結果が保存された
□ verify_article_project.pyが成功した
```

すべて満たして初めてSTEP 2へ進む。
