# STEP 1.5 — Baseline Article Generation

## Goal

GitHubで固定したAgent versionを使い、**MLflowで評価可能な最初の実Article ProjectをChatGPT Workで作成する。**

STEP 2は `article.md` を生成する工程ではない。STEP 2は、STEP 1.5で生成済みの実記事を評価する工程である。

---

# 0. Prerequisites

STEP 0とSTEP 1が完了していること。

```bash
cd ~/dev/technical-blog-work-agent
source .venv/bin/activate
python --version
```

期待値:

```text
Python 3.14.6
```

Agent version / Git状態:

```bash
cat MANIFEST.json
git status --short
git rev-parse HEAD
git branch --show-current
```

正式Baselineに使用する場合、原則 `git status --short` は空であること。

# 1. Article Projectの保存場所を分離

Article ProjectをAgent Repositoryの中へ作らない。

```text
~/dev/
├── technical-blog-work-agent/
└── technical-blog-projects/
```

```bash
mkdir -p ~/dev/technical-blog-projects
```

# 2. Article IDとテーマを決める

```bash
export ARTICLE_ID="20260818-mlflow-m5max-001"
export PROJECTS_ROOT="$HOME/dev/technical-blog-projects"
export PROJECT_DIR="$PROJECTS_ROOT/$ARTICLE_ID"
```

例のテーマ:

```text
M5 Max環境でMLflowの公式チュートリアルを実行する
```

Article IDはMLflow Run、PROJECT_STATE、将来のQiita公開結果を結ぶ識別子なので、別の記事へ使い回さない。

# 3. Article Projectを初期化

Agent Repository rootで:

```bash
python tools/init_article_project.py \
  --projects-root "$PROJECTS_ROOT" \
  --article-id "$ARTICLE_ID" \
  --topic "M5 Max環境でMLflowの公式チュートリアルを実行する"
```

確認:

```bash
find "$PROJECT_DIR" -maxdepth 2 -type f -o -type d | sort
sed -n '1,100p' "$PROJECT_DIR/PROJECT_STATE.md"
```

この時点では `article.md` は存在しないのが正常。

```bash
test ! -e "$PROJECT_DIR/article.md" \
  && echo "OK: article.md is not created before Phase 11"
```

# 4. Agent version snapshotをArticle Projectへ保存

```bash
python tools/version_snapshot.py \
  --article-id "$ARTICLE_ID" \
  --output "$PROJECT_DIR/results/version-snapshot.json"
```

```bash
python -m json.tool "$PROJECT_DIR/results/version-snapshot.json"
```

最低限確認する:

```text
article_id
agent_version
git_commit
git_branch
git_dirty
python_version
uv_version
```

正式Baselineで `git_dirty=true` なら、そのまま正式Baseline扱いしない。

# 5. PROJECT_STATEへversion identityを転記

`$PROJECT_DIR/PROJECT_STATE.md` のVersion identityへ、`version-snapshot.json` の実値を記録する。

```text
Agent version
Git commit
Git branch
Git dirty
Model / runtime
```

# 6. ChatGPT WorkでAgentを開始

`agent/START_PROMPT.md` を開き、次を実値で埋めて今回のAgentへ渡す。

```text
Article ID
Project Directory
Agent Repository
テーマ
想定読者
```

例:

```text
Article ID: 20260818-mlflow-m5max-001
Project Directory: /Users/tera/dev/technical-blog-projects/20260818-mlflow-m5max-001
Agent Repository: /Users/tera/dev/technical-blog-work-agent
テーマ: M5 Max環境でMLflowの公式チュートリアルを実行する
想定読者: MLflowを初めて使用するエンジニア
```

# 7. Phase 1〜10を実施

`article.md` を先に要求しない。

途中成果物:

```text
research.md
hypothesis.md
experiment-plan.md
experiment-log.md
analysis.md
discussion.md
data/
logs/
images/
```

失敗も削除せず記録する。
Evidence GateでMissing Evidenceが出たら、Phase 11へ進まず不足工程へ戻る。

# 8. Evidence Gate PASS後に初めてarticle.mdを生成

生成先:

```text
$PROJECT_DIR/article.md
```

確認:

```bash
test -s "$PROJECT_DIR/article.md" \
  && echo "OK: real article.md exists" \
  || echo "ERROR: article.md is missing or empty"

sed -n '1,100p' "$PROJECT_DIR/article.md"
```

`article.md` は実際のEvidenceを使ったQiita記事候補。空ファイル、ダミー記事、架空結果は禁止。

# 9. Quality Review

Phase 12まで進める場合:

```text
$PROJECT_DIR/results/quality-review.json
```

まだQuality Reviewを実行しないなら空JSONを作らない。

# 10. Agent Repositoryがdirtyになっていないことを再確認

```bash
cd ~/dev/technical-blog-work-agent
git status --short
```

記事生成だけなら、Article Project由来の変更がAgent Repositoryに出ていないことが期待される。
Agent自身を修正した場合は、その変更を新しいGit commitとして管理してから再評価する。

# 11. STEP 2へ渡すもの

必須:

```text
$PROJECT_DIR/article.md
```

任意:

```text
$PROJECT_DIR/results/quality-review.json
```

追跡用:

```text
$PROJECT_DIR/PROJECT_STATE.md
$PROJECT_DIR/results/version-snapshot.json
```

これで初めてSTEP 2へ進む。

# Completion check

```text
□ Agent RepositoryとArticle Projectが分離されている
□ Article IDを決めた
□ tools/init_article_project.pyでProjectを初期化した
□ PROJECT_STATE.mdが存在する
□ version-snapshot.jsonが存在する
□ Agent version / Git commitをProjectに記録した
□ ChatGPT WorkでPhase 1から実行した
□ Evidence Gateを省略していない
□ article.mdはPhase 11で実内容として生成された
□ article.mdは空でない
□ 架空Evidenceを入れていない
□ STEP 2へ渡すProject Directoryが確定した
```
